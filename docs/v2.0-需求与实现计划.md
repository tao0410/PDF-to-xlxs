# PDF 提取工具 v2 — 需求文档 & 实现计划（已对齐）

---

## 一、需求概述

将 PDF 信息提取工具从单一"坐标框选"升级为支持**三种提取模式**的通用工具：

| 模式 | 标识 | 适用场景 |
|------|------|---------|
| 坐标提取 | `coordinate` | 排版完全固定的 PDF |
| 关键词匹配 | `keyword` | 键值对表单（标签固定、位置可变） |
| 表格结构识别 | `table` | 不定行数的表格数据 |

每个字段独立选择提取模式，三种模式可混合使用。

**核心约束**：
- 技术栈不变：Python 3.8 + PyQt5 + pdfplumber + PyMuPDF + openpyxl
- 不引入任何新依赖
- 完全向后兼容旧配置文件

---

## 二、已对齐的关键决策

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 表格多行输出 | **方案 A**：一个 PDF 产生多条 Excel 记录，关键词字段值自动重复填充 |
| 2 | 配置命名 | 顶层 key 用 **`rules`**，数据类型值沿用旧版**中文**（文本/数字/日期/列表） |
| 3 | 预览窗口模式区分 | 增加**模式标记**，不同模式 emit 不同信号、显示不同操作提示 |
| 4 | 关键词高亮 | **需要高亮**，测试 PDF 时用半透明矩形标注匹配位置 |
| 5 | 隐式表格参数 | **暴露高级选项**，在 UI 中增加可折叠的"高级选项"区域 |

## 三、提取模式详细规格

### 3.1 坐标提取（coordinate）

完全保留现有逻辑：`page.within_bbox()` → `extract_text()`。

### 3.2 关键词匹配（keyword）

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `keyword` | string | 必填 | 搜索关键词，模糊匹配（包含即可） |
| `direction` | enum | `right` | `right` / `below` / `left` / `above` |
| `range` | int | `200` | 搜索范围（像素），可配置 50–500 |
| `page_range` | string | `第1页` | 同现有格式 |

**算法**：
1. `page.extract_words()` 获取所有词块
2. 搜索 text 包含 `keyword` 的词块
3. 以该词块边界为基准，按 direction 和 range 划定搜索区域
4. 收集区域内词块，拼接后 `_clean_text()` 清理
5. 支持跨词块搜索：关键词词块后方无值时，搜索同行右侧邻近词块

### 3.3 表格结构识别（table）

**配置参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `table_region` | [x1,y1,x2,y2] | 必填 | 整个表格区域坐标（用户框选） |
| `column_mapping` | dict | 必填 | `{"识别列名": "输出字段名"}` |
| `page_range` | string | `第1页` | 页码范围 |
| `table_settings` | dict | 默认值 | 隐式表格检测参数（高级选项） |

**高级选项**（可折叠，默认隐藏）：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `vertical_strategy` | `text` | 列检测策略：`lines`/`lines_strict`/`text`/`explicit` |
| `horizontal_strategy` | `text` | 行检测策略：同上 |
| `intersection_y_tolerance` | `3` | Y 轴交点容差 |
| `intersection_x_tolerance` | `3` | X 轴交点容差 |
| `snap_y_tolerance` | `3` | Y 轴对齐容差 |
| `snap_x_tolerance` | `3` | X 轴对齐容差 |

**算法**（使用 pdfplumber 原生 `extract_tables()`）：
1. 按 `table_region` 裁剪页面：`page.within_bbox(bbox)`
2. 调用 `cropped.extract_tables(table_settings)` 识别表格
3. 取第一个表格（或最大的表格），其第一行为表头
4. 根据 `column_mapping` 将表头列名映射为输出字段名
5. 返回多行数据，每行为 `{字段名: 值}` 字典

## 四、配置文件格式

### 4.1 新格式

```json
{
  "rule_name": "ECO工程更改单提取规则",
  "rules": [
    {
      "name": "ECO编号",
      "mode": "keyword",
      "keyword": "编号",
      "direction": "right",
      "range": 200,
      "page_range": "第1页",
      "data_type": "文本"
    },
    {
      "name": "更改内容表",
      "mode": "table",
      "table_region": [50, 130, 540, 420],
      "page_range": "第1页",
      "column_mapping": {
        "更改对象编号": "零件编号",
        "改后版本": "改后版本",
        "更改内容": "更改描述"
      },
      "table_settings": {
        "vertical_strategy": "text",
        "horizontal_strategy": "text"
      },
      "data_type": "列表"
    }
  ]
}
```

### 4.2 旧格式兼容

旧格式 `regions` 加载时自动映射：每项 mode=`"coordinate"`，`data_type` 从原字段读取。保存时不改变原有结构。

## 五、数据流变更（方案 A：多行输出）

### 5.1 变更前（v1）

```
PdfExtractor.extract_single() → {fields: {name: str}}
                                     ↓
ExtractionWorker → 每个 PDF 一个 result
                                     ↓
MainWindow → 每条 result 生成一个 content record
```

### 5.2 变更后（v2）

```
PdfExtractor.extract_single() → {records: [{name: str}]}  ← 列表！
                                     ↓
ExtractionWorker → 每个 PDF 可能产生多条 record
                                     ↓
MainWindow → 展开 records，关键词字段值自动重复填充
```

### 5.3 result 结构变化

```python
# v1
result = {"source_file": ..., "status": ..., "fields": {"编号": "xxx"}, "field_issues": {}}

# v2  
result = {"source_file": ..., "status": ..., "records": [{"编号": "xxx", "零件编号": "A"}, {"编号": "xxx", "零件编号": "B"}]}
# records: 至少包含一条记录。所有 mode 都按 records 格式输出（含 coordinate/keyword）。
```

## 六、UI 变更

### 6.1 config_dialog.py 重构

**规则表格**，每行对应一个提取规则：

| 列名 | 控件 | 说明 |
|------|------|------|
| 字段名 | QLineEdit | 输出列名 |
| 提取模式 | QComboBox | 坐标提取 / 关键词匹配 / 表格提取 |
| 动态参数 | QWidget（动态切换） | 见下方 |

**动态参数面板**按模式切换：

- **坐标模式**：页面范围 + X1/Y1/X2/Y2 + 数据类型 + "选择PDF预览并框选"按钮
- **关键词模式**：关键词 + 方向(下拉) + 范围(数字) + 页面范围 + 数据类型 + "测试关键词"按钮
- **表格模式**：页面范围 + "框选表格区域"按钮 + 列名映射子表 + "▸ 高级选项"折叠面板

**"测试关键词"按钮**：打开 PDF 预览 → 搜索当前规则的关键词 → 高亮显示并弹出结果预览。

**"框选表格区域"按钮**：打开 PDF 预览（table 模式）→ 用户框选整表 → 回传坐标 → 自动识别列名填充到映射子表。

**列名映射子表**：两列——"识别列名"(只读，自动填充) + "输出字段名"(用户编辑)。用户勾选需要的列、自定义输出名。

### 6.2 pdf_preview_dialog.py 改动

**新增模式标记**：
```python
class PdfPreviewDialog(QDialog):
    def set_mode(self, mode: str):
        """设置预览模式: 'coordinate' | 'keyword' | 'table'"""
        self._mode = mode
        if mode == 'coordinate':
            self.setWindowTitle("PDF预览 — 坐标框选")
            self.lbl_status.setText("请框选要提取的区域")
        elif mode == 'keyword':
            self.setWindowTitle("PDF预览 — 关键词测试")
            # 自动搜索并高亮
        elif mode == 'table':
            self.setWindowTitle("PDF预览 — 表格区域框选")
            self.lbl_status.setText("请框选整个表格区域")
```

**坐标框选保持原样**（coordinate 模式），新增：
- `keyword_highlight_requested` 信号（携带关键词列表）
- `table_region_confirmed` 信号（携带四角坐标，用于 table 模式）
- 关键词高亮：使用 PyMuPDF 的 `page.search_for(keyword)` + `page.draw_rect()` 绘制半透明覆盖

### 6.3 main_window.py 改动

适配 `result["records"]` 列表结构：
- `_on_extraction_finished()`：将 records 展平，每条 record 加上 `SOURCE_COL`（来源文件名）
- 确认对话框中每个 PDF 可能对应多条预览行
- `_content_columns()` 从 `ConfigManager.get_column_names()` 获取列名（需包含 table 模式中 column_mapping 的输出字段名）

### 6.4 确认对话框改动

- 单文件确认（`SingleConfirmDialog`）：展示多行记录，支持逐行编辑
- 批量确认（`BatchConfirmDialog`）：所有 PDF 的所有行展开显示，行数 = 各 PDF 记录数之和

## 八、验证方案

1. **坐标模式回归测试**：用旧 `default.cfg`（regions 格式），确认提取结果不变
2. **关键词模式测试**：用 ECO PDF 测试"编号""产品型号"等关键词提取

5. **批量测试**：3-5 份同类型 PDF，确认准确率
6. **高级选项测试**：调整 table_settings，确认隐式表格检测行为变化
7. **兼容性测试**：加载旧 v1 配置文件，确认正常使用
