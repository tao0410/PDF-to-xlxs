## 迭代背景

v1.0 已完成单文件/批量 PDF 提取→确认→导出 Excel 的核心闭环。在实际使用中发现三个效率瓶颈，本次迭代针对性解决。

## 功能一：一键清空全部已确认内容

### 现状问题

已确认内容表格仅支持"删除选中行"逐行删除。完成一批 PDF 处理后，用户常需手动逐行清空总表以开始下一批任务，操作繁琐。

### 功能描述

在已确认内容表格下方的按钮区域新增 **「清空全部」** 按钮。点击后弹出确认对话框，用户确认后清空全部已确认记录。

### 交互流程

```
用户点击「清空全部」
  → 弹出确认对话框："确定清空全部已确认内容？（共 N 条记录）"
    → 用户点「确定」：清空全部 confirmed_records，刷新表格，保存会话
    → 用户点「取消」：不做任何操作
```

### 验收标准

- 按钮位于「已确认内容」表格下方，「添加行」按钮左侧
- 有数据时按钮可用，无数据时置灰禁用
- 清空前弹出确认对话框，显示待清空记录数
- 清空后表格立即刷新，统计文案更新为"共0条记录"
- 清空操作触发会话保存

## 功能二：Excel 导出成功后自动清空

### 现状问题

一次完整的处理流程为：选择文件 → 提取 → 确认 → 导出 Excel。导出后用户通常开始下一轮处理，但文件列表和已确认内容表格仍保留上一轮数据，需手动清空。

### 功能描述

导出 Excel 成功后，在用户关闭成功提示对话框（点击"关闭"按钮，而非"打开文件"/"打开文件夹"）时，自动清空文件列表和已确认内容表格。

### 交互流程

```
用户点击「生成Excel」
  → 选择保存路径
  → 导出成功 → 弹出提示框：
      [打开文件] [打开文件夹] [关闭]
    → 用户点「关闭」：
      → 自动清空 self.files（文件列表）
      → 自动清空 self.confirmed_records（已确认内容）
      → 刷新两个表格
      → 保存会话
    → 用户点「打开文件」或「打开文件夹」：仅打开，不清空
```

### 验收标准

- 仅在导出成功 + 用户点击"关闭"后触发清空
- 导出失败不触发清空
- 点击"打开文件"或"打开文件夹"不触发清空
- 清空范围为文件列表 + 已确认内容表格，两处同步清空
- 清空后保存会话

## 功能三：配置规则时可多次框选（同一 PDF 不重复打开）

### 现状问题

当前配置规则流程：选中一行规则 → 点击「选择PDF预览并框选」→ 打开 PDF → 框选一个区域 → 点击「确认坐标」→ **对话框立即关闭**。如需配置多个提取字段，每添加一个规则就需重新打开 PDF，重复次数等于规则行数，操作非常低效。

### 功能描述

打开 PDF 预览窗口后，窗口**保持在打开状态**，用户可在配置规则表格中切换不同行，对每个规则行依次框选坐标，点击「确认坐标」后坐标自动填充到当前选中的规则行，PDF 预览窗口不关闭。全部规则配置完毕后，手动关闭 PDF 预览窗口。

### 交互流程

```
用户在配置规则表中选择第 1 行（如"编号"）
  → 点击「选择PDF预览并框选」
  → 打开 PDF 预览窗口
  → 在 PDF 上框选"编号"区域
  → 点击「确认坐标」→ 第 1 行坐标自动填充
  → 预览窗口保持打开，显示"坐标已填充到：编号"

用户在配置规则表中选择第 2 行（如"名称"）
  → 在已打开的 PDF 预览窗口上框选"名称"区域
  → 点击「确认坐标」→ 第 2 行坐标自动填充
  → 预览窗口保持打开，显示"坐标已填充到：名称"

... 重复操作，直到所有规则行配置完毕 ...

  → 点击「关闭」→ 关闭 PDF 预览窗口
```

### 验收标准

- 点击「确认坐标」后 PDF 预览窗口不关闭
- 坐标填充到配置规则表中**当前选中**的行（实时获取选中行，而非打开时的固定行）
- 若配置规则表中无选中行，点击「确认坐标」时提示"请先在规则表中选择目标行"
- 同一 PDF 上可多次框选不同区域，分别填充到不同规则行
- 点击「关闭」正常关闭 PDF 预览窗口
- PDF 预览窗口的翻页、缩放、清除框选功能正常运行
